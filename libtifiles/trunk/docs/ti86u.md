# Community TI-86 OS update files (.86u)

TI86U 1.0 reuses the 78-byte `**TIFL**` header and TI's Z80 page-oriented
TI-HEX encoding. This is a newly defined community container, not a recovered
vendor package. Owner ID `0x86` is proposed, not TI-assigned. The payload is the
complete 256 KiB target ROM; the native link installer is generated by libticalcs.

All offsets below are hexadecimal:

| Offset | Size | Required value |
| --- | ---: | --- |
| `00` | 8 | ASCII `**TIFL**` |
| `08` | 2 | Outer profile revision `01 00` |
| `0A` | 1 | Encoding `01` (TI-HEX text) |
| `0B` | 1 | Object `88` (Z80) |
| `0C` | 4 | Date zero (unknown) |
| `10` | 1 | Literal OS version length, `1..8` |
| `11` | 31 | ASCII digits separated by single dots, zero-padded |
| `30` | 1 | Owner/device `86` |
| `31` | 1 | OS type `23` (`TI86_AMS`) |
| `32` | 23 | Zero padding, no additional owner/type pairs |
| `49` | 1 | Hardware/product ID zero |
| `4A` | 4 | ASCII payload size, unsigned little-endian |
| `4E` | variable | TI-HEX records |

The fixed outer revision is separate from the literal target version in the
name (`0.2026`, `1.1003`, `1.6`, etc.). The label is metadata; this parser does
not authenticate it against ROM strings or prove package provenance.

Each TI-HEX record is `:LLAAAATT[DATA]CC`, at most 32 data bytes, with the usual
Intel HEX byte-count and two's-complement checksum. Type `02`, address zero,
two-byte big-endian data selects physical ROM page `0..15`. This is **TI page
selection**, not a generic Intel HEX segment base. Type `00` supplies sequential
nonempty data at addresses `4000..7FFF`. Every page must contain all 16 KiB,
including erased bytes and the final ROM byte. The extracted ROM offset is
`page * 0x4000 + address - 0x4000`. Uniform storage window `4000..7FFF` also
applies to page zero; it does not describe the reset-time CPU mapping.

There is one final type `01` record, address zero, no data. No section toggles,
extra objects, signatures or trailers are permitted. Whole pages may appear in
any order. The reader also accepts lowercase hex, shorter nonempty records and
CR/LF/CRLF endings. The canonical writer emits pages in the order supplied by
the content object, 32-byte uppercase data records, CRLF, and the final
`:00000001FF` without a newline. Sorted pages `0..15` produce exactly 631,145
bytes: 78 header bytes and 8,209 records / 631,067 payload bytes.

The TI-86 reader checks the full header, exact payload boundary, checksums,
record types, address continuity, complete unique pages and final EOF before
returning any content. It normalizes the in-memory page array into page order.
An owner/model/destination mismatch is rejected; renaming an `.8xu` is not a
conversion. Ordinary `.86k` constants retain their existing meaning.

`FlashContent.data_length` is 262,144 after parsing, following the existing
legacy Z80 API convention; the on-disk header length counts ASCII bytes. OS
pages use `addr=0x4000`, `size=0x4000`, `flag=0x80`, `page=0..15`.
The ROM's own checksum is preserved even if invalid; no signing or automatic
repair is performed.

## Sending through libticalcs / WebTiLP

`ticalcs_calc_send_os2(handle, filename)` parses `.86u` and uses the TI-86
`send_os` driver. WebTiLP's normal OS-file route calls that API. Rebuild both
the tilibs WASM archives and the WebTiLP module after updating the source:

```sh
./build_wasm.sh
make -C webtilp dev
make -C webtilp test-ti86-os-wasm
```

Connect/select TI-86 while the calculator is running normally, then enter its
native updater: **2nd -> MORE (MODE) -> ALPHA -> LN (F)**. It should display
**Waiting** before sending the `.86u` file. This native entry is present in the
supplied `0.2014`, `0.2026`, `1.1003`, `1.2003`, `1.4001` and `1.4010` images.
The ordinary ready/device-info protocol is not used in OS mode.

The native updater uses host MID `05`, replies as MID `85`, and accepts native
10-byte descriptors of type `16`; these values are separate from container
owner `86` / OS type `23`. Each block is a descriptor, ACK/CTS exchange, host
ACK, 256 data bytes, and a final calculator ACK. Both descriptor ACK/CTS carry
header word `000A`; data ACK carries `0100`, without following payloads.

The sender checks all 16 pages before any traffic, writes pages `0..14`, stages
target page `0F` in bank-B RAM at `8000..BFFF`, uploads the reconstructed
finalizer to `C600`, and redirects the writer return through `FB00..FBFF`.
The 39-byte finalizer (source: `libticalcs/trunk/src/ti86_os_finalizer.asm`)
uses the native RAM programmer at `C087` for the last page and resets. This
strategy is independent of the six known receiver layouts, and always sends
1,026 records / 289,332 host bytes. There is no final EOT after the handoff.
The final ACK precedes programming; the sender waits one second for the tail.

The RAM finalizer is reconstructed software, not recovered TI installer code.
The verified emulator requires TilEm's opt-in programmable development ROM
model. Physical development hardware and real cable timing remain untested;
retail mask ROM is not made writable by this file format. Retail `1.2..1.6`
images lack the built-in receiver, so installing one removes this native route
for another update. Returning requires a separately bootstrapped receiver or
external programming, neither supplied here. The sequence is not a power-loss
recovery design.

## Tests

The aggregate CMake `check` target and Automake tests include synthetic parser,
writer-state and sender tests. Rejections cover malformed headers, checksums,
gaps, short/duplicate/missing pages, extra bytes/objects and crossed models.
Sender tests include the actual filename API, reordered memory pages, complete
wire framing, cancellation, bad ACK/CTS, checksum errors and cable timeouts.
`make -C webtilp test-ti86-os-wasm` additionally uses the actual WebTiLP bridge
and a scripted cable, including OS metadata and malformed-file cleanup.

Optional ROM-backed integration uses a separately supplied TilEm source tree
with programmable TI-86 support (`782517e` or later), ROMs and a `.86u` file:

```sh
cmake -S . -B /tmp/tilibs-ti86-test -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DBUILD_SHARED_LIBS=OFF -DTILEM_SOURCE_DIR=/path/to/tilem-headless
cmake --build /tmp/tilibs-ti86-test --target ti86_os_emulator
/tmp/tilibs-ti86-test/libticalcs/trunk/tests/ti86_os_emulator \
  /path/to/TI86_0.2026.rom /path/to/TI86_1.1003.86u /path/to/TI86_1.1003.rom
```

This test boots by ordinary key input, connects libticalcs' real cable callbacks
to the running emulator, and compares every final ROM byte. Its cable adapter
advances one millisecond of emulator time after each receive callback to model
turnaround; the emulated CPU runs only inside those callbacks. No generated
DBUS replay file or host-side target ROM write is involved. It does not claim
physical hardware validation. No ROM payloads are bundled in these tests.
